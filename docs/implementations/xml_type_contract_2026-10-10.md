# Transparent XML tuple contract (#27)

## Scope and changes

The user explicitly chose public, transparent tuples rather than opaque trees
and accessor functions. `signerl_xml:simplified_xml/0` remains an exported `-type`.
The existing scoped Elvis exception is intentional; its comment now describes
the public contract rather than calling the tree a simplified xmerl tree.

- `src/signerl_xml.erl` adds binary text to the recursive tree type and a shared
  attribute-value type used by the tree and both attribute lookup specs.
  Character lists, UTF-8 binaries, integers, and existing atoms reflect the
  exporters' and canonicalizers' supported ordinary attribute values. Replace
  `number()` with `integer()` because float serialization is unsupported.
- Decode binary text and attributes as UTF-8 before xmerl escaping. xmerl's
  binary handling previously treated each byte as a code point, corrupting
  caller-built non-ASCII values when the exporter encoded its output as UTF-8.
  Existing escaping and the explicit tree traversal stack are preserved.
- Five focused EUnit cases exercise caller-built mixed-content trees, exact
  exported bytes, parse/export values, lookup helpers, and both canonicalizers.
- README documents tuple ownership, allowed values, parse normalization, and
  namespace declaration values (character lists for canonicalization).
  `test/TESTS.md` updates the responsibility map and count to 308 cases.

No opaque wrapper, new accessor API, or new error-handling branches are added.
Names remain UTF-8 binaries. Namespace URI matching and other namespace behavior
remain #41; this type is not a substitute for XML/name/namespace validation.

## Validation-first evidence

Before production changes, 85 XML EUnit cases ran and the two new binary-value
cases failed: exported UTF-8 was double encoded (for example `café` became
`cafÃ©`). The remaining three new attribute representation cases passed.

An external caller compiled with debug information also failed Dialyzer against
the baseline production module. It returned a binary-text/binary-attribute tree
with a `signerl_xml:simplified_xml()` spec, pattern-matched the tree name, and
called `attr_value/2` with a binary value. Dialyzer reported invalid contracts
and a call breaking the old attribute contract. The same caller passes against
the fixed production module. Negative controls still report invalid contracts
for atom element names and float attribute values. Changing only the type to
`-opaque` in a task-owned copy rejects the caller's tuple construction, confirming
why opacity is incompatible with the chosen public API.

The positive consumer is:

```erlang
-module(xml_contract_consumer).
-export([tree/0, inspect/1, binary_attribute/0]).
-spec tree() -> signerl_xml:simplified_xml().
tree() -> {<<"root">>, [{<<"value">>, <<"value">>}], [<<"text">>]}.
-spec inspect(signerl_xml:simplified_xml()) -> binary().
inspect({Name, _, _}) -> Name.
-spec binary_attribute() -> {ok, binary()}.
binary_attribute() -> signerl_xml:attr_value(<<"value">>, [{<<"value">>, <<"value">>}]).
```

To repeat, compile the consumer with `erlc +debug_info`, then analyze its BEAM
alongside `_build/default/lib/signerl/ebin/signerl_xml.beam` using `dialyzer`
and the dependency PLT generated by `rebar3 dialyzer`. The source, compiled
positive/negative/opaque controls, exact diagnostics, and baseline run are saved
in the persistent recovery directory below. The validation used the same OTP
28.4.2 dependency PLT from the completed #61 checkout; the project module itself
was always supplied explicitly to Dialyzer, using the baseline or updated BEAM.
