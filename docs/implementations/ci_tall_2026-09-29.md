# Issue #12: one complete CI quality gate

## Change and reasoning

Issue #12 asks GitHub CI to run `rebar3 tall`. The old alias was not usable as the required aggregate gate: it omitted lint, referenced a nonexistent `config/sys.config`, and failed Xref on library functions called by external consumers or tests.

- `rebar.config`: compose `tall` from `test`, `lint`, `xref`, and `dialyzer`. Reusing the existing test alias keeps formatting, EUnit, Common Test, and the 100% coverage threshold in one place and removes the unnecessary distributed CT node and missing configuration argument. `flint` remains the standalone formatter/linter command; the aggregate runs each of those providers once.
- `rebar.config`: explicitly check undefined calls/functions, unused local functions, and deprecated calls/functions. Do not infer unused exported APIs from the library-only application graph. Do not ignore individual public function bodies.
- `rebar.config`: reset collected coverage before each test run so old results in persistent build caches cannot change the current coverage verdict.
- `.github/workflows/erlang.yml` and `scripts/ci_local_docker.sh`: use `rebar3 tall` after certificate preparation, so CI and the local matrix use the same complete command.
- `scripts/ci.Dockerfile` and `scripts/ci_local_docker.sh`: build a test image with `libxml2-utils`, matching Linux CI's `xmllint` prerequisite for the existing canonicalization interoperability cases. Keep the existing OTP base images and named build/cache volumes.
- `README.md`: document the aggregate gate and contribution workflow.
- `AGENTS.md`: persist the user's investigate → behavioral validation → implement/test → self-review/simplify/retest → full tests/100% coverage → flint → Dialyzer → tall → commit/push/PR workflow. Record one PR per issue, target `dev`, and ready-for-review PRs after passing checks. Also retain the user's CodeGraph-first preference.

No signing/verification behavior, plugin version, or supported OTP matrix changed. Formatter/cache reproducibility remains issue #60; OTP and lint upgrades remain #62/#63. The existing formatter still writes changes, so inspect the final diff after the gate; a non-mutating format check belongs to #60.

## Validation-first work and self-review

Before implementation, the existing `tall` command failed Xref on seven externally/test-used exports. A separate minimal library fixture using the repository's actual `rebar.config` and `elvis.config` reproduced the failure on the public `signerl:sign/3` entry point despite passing its EUnit control.

Validation uses a disposable minimal library with one binary-in/binary-out function and independent EUnit/CT assertions. It runs the real Rebar providers with intentional defects, rather than asserting that configuration text contains particular commands. The cases are a passing baseline, failing EUnit assertion, failing CT assertion, uncovered function, lint violation, disjoint type specification, and an undefined call inside the public function. The undefined-call case invokes Xref directly to isolate that check from earlier test/coverage failures.

Self-review followed the repository's `ferike` checklist. The first attempt used individual Xref ignores; the undefined-call probe showed that these also hide broken calls inside ignored public functions. Replaced them with explicit library-appropriate checks and reran validation. The corrected implementation is smaller and keeps public function bodies checked. No production-module edits or custom runtime test framework are needed for this CI configuration change.

The full project gate also exposed an erlfmt `exit:normal` internal error when formatting ran a second time after Xref, although the individual commands and small positive fixture passed. Removed the duplicate formatter invocation: `test` already formats, so `tall` calls `lint` directly afterward. Reran validation against the adjusted aggregate rather than accepting only the separate commands as evidence.

After Docker became available, the first matrix attempt skipped seven cases because `xmllint` was missing and reported 75% coverage while importing old EUnit data from a persistent build volume. Added the missing image prerequisite and Rebar's native coverage reset. A separate warm-cache probe demonstrated the opposite risk as well: old EUnit coverage incorrectly let an untested function pass the old aggregate. With the reset, the same fixture correctly failed at 50% coverage. All original fault-injection probes passed again after this change.

## Final validation

Test certificates were generated in the isolated worktree. Rebar commands use `REBAR_GLOBAL_CONFIG_DIR=/private/tmp/signerl-rebar-global` to avoid the user's unrelated global `rebar3_run` plugin; no user-global configuration was edited. Final validation used the official rebar3 3.25.1 release executable downloaded into a temporary directory and local OTP 28.4.2. The repository's version pins were not changed in this issue.

- The disposable fixture's positive aggregate passed. Intentional EUnit, CT, coverage, lint, and Dialyzer defects each made `tall` fail at the expected provider. Xref rejected an undefined call inside the public function. Native Rebar clean commands ran between fixture cases to avoid stale compiled tests when files were rewritten within the same filesystem timestamp interval.
- `rebar3 test`: 14 EUnit tests and 195 CT cases passed, no skips, with 100% coverage across all ten modules.
- `rebar3 as test cover`: 100% total coverage.
- `rebar3 flint`: passed.
- `rebar3 dialyzer`: passed with no project findings. The earlier PLT-building run printed OTP xmerl missing-spec diagnostics; the final run was clean.
- `rebar3 tall`: passed on the final implementation, including all 14 EUnit tests, 195 CT cases, 100% coverage, lint, Xref, and Dialyzer.
- `bash -n scripts/ci_local_docker.sh` and `git diff --check`: passed. The formatter did not introduce unrelated source/fixture changes.
- `make ci-local`: passed on Linux OTP 26, 27, and 28 using the existing named build/cache volumes. Each version passed 14 EUnit tests and 195 CT cases with no skips, 100% coverage across all ten modules, lint, Xref, and Dialyzer. Windows execution remains a GitHub CI check.

Final self-review found no remaining blocking implementation issue within #12. The retained write-mode formatter and unpinned tooling are known follow-up work in #60, not newly introduced behavior. The workflow was also saved to the original checkout's `AGENTS.md` so it is available immediately without moving the user's existing review/roadmap files.

The local Docker credential helper stalled image builds. The successful retry uses a temporary empty Docker client configuration and an explicit connection to the existing daemon for these public images; no user Docker settings or credentials were changed. No required gate was waived.
