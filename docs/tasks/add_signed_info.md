# Task: add_signed_info

## 1. Goal
Move signature generation and verification toward XMLDSig `ds:SignedInfo` structure, and bind XAdES `xades:SignedProperties` through a dedicated `ds:Reference`, while explicitly deferring canonicalization to a later task.

## 1.1 Non-Goal
This task does not target external XMLDSig/XAdES validator interoperability yet; output remains an internal deterministic profile until canonicalization is implemented.

## 2. Why This Is Needed
Current signing verifies a project-local payload, but introducing `ds:SignedInfo` now gives us the correct structural base for the next standards-alignment step.

## 3. Scope
- In scope:
  - Add `ds:SignedInfo` to produced signatures.
  - Add `ds:CanonicalizationMethod`, `ds:SignatureMethod`, and `ds:Reference` nodes.
  - Add digest validation for all `ds:Reference` entries during verify.
  - Add explicit `ds:Reference` to `xades:SignedProperties` with the XAdES Type URI.
  - Keep existing public API (`sign/3`, `verify/3`).
- Out of scope:
  - Canonicalization implementation and strict C14N behavior.
  - Full XAdES Baseline-B profile completion beyond current property set.
  - Timestamp/OCSP/certificate-chain validation logic.

## 4. Fixed Profile For This Task
Use one deterministic profile (no configuration yet):
- Canonicalization declaration only (no implementation yet):
  - emit `ds:CanonicalizationMethod Algorithm="http://www.w3.org/2006/12/xml-c14n11"` in `ds:SignedInfo`
  - actual canonicalization logic is deferred
- Document reference (`URI=""`) transforms:
  - `http://www.w3.org/2000/09/xmldsig#enveloped-signature`
  - canonicalization transform handling is deferred
- SignedProperties reference:
  - `URI="#SignedProperties-1"`
  - `Type="http://uri.etsi.org/01903#SignedProperties"`
  - digest over current project-local deterministic bytes (same internal method as today)

## 5. Target XML Shape (Conceptual)
- `ds:Signature Id="Signature-1"`
  - `ds:SignedInfo`
    - `ds:CanonicalizationMethod Algorithm="...xml-c14n11"`
    - `ds:SignatureMethod Algorithm="..."`
    - `ds:Reference URI=""`
      - `ds:Transforms`
      - `ds:DigestMethod`
      - `ds:DigestValue`
    - `ds:Reference URI="#SignedProperties-1" Type="http://uri.etsi.org/01903#SignedProperties"`
      - `ds:DigestMethod`
      - `ds:DigestValue`
  - `ds:SignatureValue`
  - `ds:Object`
    - `xades:QualifyingProperties Target="#Signature-1"`
      - `xades:SignedProperties Id="SignedProperties-1"`

## 6. Implementation Plan

### Iteration 1: XML Builders And Algorithm Mapping
1. Add helpers to build `ds:SignedInfo` and its child elements.
2. Add internal mapping from current hash/key inputs to:
   - `ds:SignatureMethod` URI
   - `ds:DigestMethod` URI
3. Ensure required IDs are generated/set deterministically (`Signature-1`, `SignedProperties-1` for now).

Acceptance:
- Signed XML includes complete `ds:SignedInfo` and both references.

### Iteration 2: Canonicalization + Digest Pipeline
1. Add canonicalization utility for selected nodes (`SignedInfo`, referenced nodes).
2. Implement reference digest calculation pipeline:
   - apply transforms for document reference,
   - canonicalize,
   - digest,
   - base64 encode into `ds:DigestValue`.
3. Compute `ds:SignatureValue` by signing canonicalized `ds:SignedInfo` bytes.

### Iteration 2: Internal Deterministic Digest/Signature Pipeline (No C14N Yet)
1. Implement `ds:Reference` digest calculation using current project-local deterministic bytes.
2. Compute `ds:SignatureValue` from deterministic `SignedInfo` bytes generated by the same exporter/parser pipeline.
3. Keep algorithm URIs present in XML, but do not claim external XMLDSig interoperability yet.

Acceptance:
- Produced `DigestValue` and `SignatureValue` are deterministic and stable within this project profile.

### Iteration 3: Verification Refactor
1. Parse and validate required structure of `ds:SignedInfo`.
2. Verify each `ds:Reference` digest before crypto signature verification.
3. Rebuild deterministic `ds:SignedInfo` bytes (project-local) and verify `ds:SignatureValue` against that form.
4. Keep current error contract:
   - malformed/missing required elements -> `{error, invalid_signature}`
   - cryptographic mismatch -> `false`

Acceptance:
- Tampering with either signed document content or signed properties fails by reference digest mismatch.

### Iteration 4: Tests, Fixtures, Docs
1. Add positive fixtures for valid SignedInfo signatures.
2. Add negative fixtures for:
   - missing `SignedInfo`
   - missing required references
   - wrong `SignedProperties` Type URI
   - wrong digest value in either reference
   - wrong `SignatureValue`
3. Update docs/examples and add implementation log.

Acceptance:
- All quality gates pass and coverage remains 100%.

- Reference transform semantics are declared but only partially enforced until C14N task is completed.
- ID/URI handling bugs can silently sign the wrong node set.
