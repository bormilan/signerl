# XML extraction equivalence and security report — #88

The pre-extraction oracle is Signerl
[`5927e41bab8674b875c51df1a1ec956d42676992`](https://github.com/bormilan/signerl/tree/5927e41bab8674b875c51df1a1ec956d42676992).
The extracted implementation is the real HTTPS/Git dependency xmlan
[`1fe39f6d414217584f514e70e43b8e7b4171f1ef`](https://github.com/bormilan/xmlan/tree/1fe39f6d414217584f514e70e43b8e7b4171f1ef),
identically pinned by `rebar.config` and `rebar.lock`. No behavior differences
were found. This task changes regression tests and their setup/documentation;
production code, signature profiles, failure policy, and original goldens are unchanged.

## Reproduce

From a checkout with the pinned OTP/rebar3 toolchain, Git, Bash, and OpenSSL:

```sh
scripts/gen_certs.sh
scripts/prepare_xml_baseline.sh
rebar3 ct --suite test/signerl_xmlan_equivalence_SUITE
rebar3 tall
```

The preparation script fetches only the full immutable baseline revision into
ignored, persistent `priv/xml-baseline`. It refuses a reused checkout with a
changed revision or dirty files. Git access is required on the first run; later
runs reuse the clean checkout. All six CI jobs run this preparation before tall.
Missing or modified baseline source fails the suite; the comparison is mandatory.

The suite verifies SHA-256 for all 25 original production/header/test files listed
in [baseline_sources.term](../test/examples/xmlan_migration/baseline_sources.term).
It compiles only the listed historical production modules, under the running OTP,
into a private test directory and loads them in an isolated peer VM. The peer
must resolve `signerl_xml` to that directory and cannot resolve xmlan. Current
observations call installed xmlan/xmlan_c14n directly; actual Signerl signing and
verification use the pinned dependency. Historical modules never enter the
current application VM or a production code path. No historical implementation
is committed or maintained as a fallback.

## Comparisons

| Executable case | Required result |
| --- | --- |
| `xml_bytes` | Exact parsed tuples, file parsing, original prolog, exported/fragment bytes, expanded-name projection, C14N 1.1 and Exclusive bytes match the baseline. |
| `rsa_same_key` | Five inputs × certificate present/absent: complete RSA signed bytes match, including SignatureValue, for identical input/key/certificate/time. Binary/file entry points agree. Both implementations verify the other's output; reconstructed current output also verifies. |
| `ecdsa_cross_verification` | Five inputs with the same EC key/certificate/time: both implementations verify the other's output; reference digests and document/property/SignedInfo canonical bytes agree. Randomized signature bytes are not compared. |
| `independent_signatures` | Both implementations verify unchanged xmlsec1 C14N 1.1 and Exclusive fixtures. Their extracted reference/canonical observations agree; current reconstruction verifies. These independent signatures are not generated by either implementation. |
| `public_errors` | Eleven malformed/prolog/encoding/namespace/DTD inputs yield identical binary/file public results and lower-level parse/prolog/file exceptions, including missing-file and invalid-date precedence. Wrong-namespace Signature and impossible signing dates retain their explicit public errors. |
| `public_file_entities` | Public sign/verify, binary and file input, reject SYSTEM/PUBLIC subsets, general/parameter entities, and relative file entities. Traced positive controls prove both file-read/open detectors work; no canary fetch occurs during the pipeline. |
| `public_http_entities` | A real loopback HTTP request proves reachability/detection. The same public entry points reject all four external DTD/entity forms without making a request. |
| `baseline_contract_ownership` | The complete baseline test inventory equals the committed mapping, without duplicates; every mapped target is still an executable EUnit contract/generator or CT case in its owner. |

The five-input corpus contains the frozen mixed-content/CDATA/reference fixture,
books, Unicode names/text/attributes, preserved content/escaping, and an explicit
inherited/default/undeclared/rebound/unused namespace case with application
`ds`/`xades` prefixes and a wrong-namespace Signature lookalike. The fixed time is
`2026-10-13T12:34:56Z`. Fresh RSA/EC keys and matching certificates are generated
once per test in memory and passed to the historical VM in memory. They are not
serialized as fixtures. Peer-call failure reporting omits key-bearing arguments.

All existing 71 public API cases also pass unchanged in scope, including valid
reconstruction controls before tampering, wrong keys, changed message/time/
certificate digests, malformed base64/metadata/reference structure, Gregorian
dates, inherited signed fragments, and independent signatures. The existing
fresh-VM dependency-backed XML/sign/verify probe still requires **zero** persistent
atom growth in each of two disjoint 25-name batches. Generic xmlan checks include
the standalone atom probe, file/HTTP canaries, 10,000-level parse/export/projection,
and both-mode xmllint comparisons. No new arbitrary-depth C14N promise is made.

## Validation evidence

Native OTP 28.4.2 / rebar3 3.25.1:

- Signerl: 150 EUnit + 84 CT = **234 passed**, all ten production modules and total
  **100% coverage**; formatting/lint, Xref, Dialyzer, and final native tall pass.
- Exact pinned xmlan: 236 EUnit + 23 CT = **259 passed**, both production modules
  and total **100% coverage**; native tall passes, including xmllint.
- Temporary negative controls fail on altered RSA output bytes, altered canonical
  bytes, a removed ownership entry, an extra file-canary read, and changed
  baseline source. Each mutation is restored before final gates; golden files
  are never regenerated.
- Fresh six-job xmlan validation of the exact pin:
  [OTP 26/27/28 on Ubuntu/Windows](https://github.com/bormilan/xmlan/actions/runs/38940721803).
  Signerl's PR records its own six-job latest-head result, including this complete
  comparison suite in tall. Required tests/checks must pass without skips.

The final source/compiled-call and clean-consumer ownership audit remains #89.
